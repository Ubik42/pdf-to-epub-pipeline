# PDF 批量转换为高质量 EPUB

## 目标产物

“高质量 EPUB”指可重排正文，而不是把每页 PDF 作为整页图片塞进 EPUB。成品至少满足：

- 章节目录可跳转，正文顺序正确；
- 标题、段落、列表、脚注、图片和图注具有明确结构；
- 中文没有大面积断行，英文跨行连字符得到校正；
- 原始插图优先从 PDF 无损提取，不从整页截图二次裁切；
- 表格优先输出 XHTML；结构不能可靠恢复时保留原表格图片；
- 公式能够可靠转换时使用 MathML，不能可靠转换时使用 SVG 或高分辨率图片并保留替代文本；
- EPUBCheck 无 fatal/error；Koodo Reader 能打开、换章、调整字号并显示图片；
- 每个章节和异常片段能够定位回源 PDF 页码。

## 文档视觉模型优先

主流程直接读取 PDF 页面图像，同时处理文字、阅读顺序、标题层级、公式、表格、图注和脚注。本地 MinerU standard 档内部结合版面模型、视觉语言模型和 OCR 组件；“直接看页面”不等于完全不用 OCR。

可靠的原生文本层可以作为字符证据；需要时可另跑独立 OCR 复核疑难字符和数字。视觉模型可能把模糊字符补成语义通顺但原文不存在的内容，因此后续要保留页码、坐标和原页引用。当前分段 Markdown 只保留页段范围，尚未具备逐页坐标审计。

| 页面 | 主路径 | 辅助路径 |
| --- | --- | --- |
| 单栏、文本层可靠 | 原生文本与坐标提取 | 页图检查标题和插图位置 |
| 文本层存在但乱码、乱序 | 文档视觉模型 | 原生文本作为字符锚点 |
| 扫描正文 | 文档视觉模型 | OCR 独立复核人名、数字和生僻字 |
| 多栏、脚注、表格、公式 | 文档视觉模型 | 版面模型和专用公式/表格识别 |
| 极低清、缺页、倾斜严重 | 预处理后双引擎识别 | 分歧过大则进入人工复核 |

禁止让通用语言模型在没有页图或字符坐标的情况下“润色”整本识别文本。文字修复只能针对有证据的候选项，并记录原值、修改值、页码、引擎和理由。

## 一本书一个长期任务

每本书在 `work/<book_id>/` 下保存独立状态：源文件指纹、已完成页段、逐页解析结果、图片资源、结构化正文、EPUB 构建结果和质量报告。中断后从最后一个完整页段继续，不重新识别已验收页面。只有全书覆盖、EPUBCheck 和阅读器抽查全部通过后，才发布到 `D:\text\BookInbox`。

当前实现以 32 页为一个解析段，段文件和 JSON 状态单独保存，并用源 PDF 的 SHA-256 防止串书。段内暂时只能定位到页码范围；逐页坐标、原文与修订审计仍属于后续建设，不应把现有 Markdown 当成已完成的逐页标准中间层。

## 流水线

### 1. 入库与指纹

计算 SHA-256，记录文件大小、页数、文本层覆盖率、语言、加密状态和基础书目信息。相同哈希只处理一次；同书不同扫描版本分别保留。

### 2. 页面分类

逐页判断 `native_text`、`scan_text`、`complex_layout`、`mostly_image` 或 `blank`。一本 PDF 可以同时包含目录文本页、扫描正文页和彩页，不能只按整本选择一个解析器。

### 3. 解析到标准中间层

解析器输出先进入中间层，不直接生成 EPUB。最小数据形态：

```json
{
  "book_id": "sha256:6c4f...",
  "source_pdf": "D:\\text\\PDFBookInbox\\运筹学（第5版）.pdf",
  "page": 42,
  "page_type": "complex_layout",
  "engine": "document_vlm",
  "blocks": [
    {
      "id": "p0042-b0007",
      "type": "paragraph",
      "bbox": [112, 486, 2284, 792],
      "text_raw": "设线性规划问题……",
      "text_normalized": "设线性规划问题……",
      "confidence": 0.97,
      "reading_order": 7
    }
  ],
  "warnings": ["formula_needs_review"]
}
```

`text_raw` 永远不覆盖；`text_normalized` 的每次变化写入审计记录。图片资产记录来源页、原始对象编号或裁切坐标以及文件哈希。

### 4. 结构规范化

确定性规则先处理页眉页脚、页码、重复水印、断行、段落合并、英文连字符和空白。章节识别结合原书目录、标题样式、页码连续性和正文交叉验证。模型只提出候选结构，不直接改写正文。

### 5. EPUB 3 打包

正文按章拆分 XHTML，生成 `nav.xhtml`、OPF manifest/spine、CSS、封面、图片和字体声明。保留印刷页码时同时生成 page-list。默认生成可重排 EPUB；只有版式本身就是内容的画册、漫画或谱面才考虑固定版式。

教材的目录层级、图注、表题、例题和公式按 [EPUB 排版标准](EPUB_STYLE_STANDARD.md) 处理。导航目录应覆盖印刷目录中的节和习题，而不仅是章。

### 6. 自动验收

- EPUBCheck：不允许 fatal/error；
- 完整性：输入有效页覆盖率、章节数量、图片引用和资源清单一致；
- 文本：抽查开头、中段、结尾，人名、数字、公式和表格各选代表页；
- 结构：目录目标存在，spine 顺序正确，无空章节和重复正文；
- 回归：用 Koodo Reader 导入并检查封面、目录、换章、字号、图片和搜索。

现有 `scripts/audit_epub.py` 可检查页段覆盖、源文件指纹、EPUB 结构、图片资源和 EPUBCheck 结果。自动验收只能证明文件结构与处理范围，不能证明每个公式、数值和表格均识别正确；此类内容还需对照原始扫描页复核。

### 7. 发布与隔离

验收通过的 EPUB 复制到 `D:\text\BookInbox`，由现有 Koodo 自动化接管。缺页、解析分歧、正文覆盖不足或验证失败的书保留在工程 `work/`，标记为 `needs_review`，不发布到书库。

## 基准集与后端选择

先用约 30 页人工标注样本比较候选解析器，不以单张“看起来不错”的页面决定技术路线。样本至少包括：

- 简体中文横排正文 5 页；
- 英文正文和断词 5 页；
- 目录、页眉页脚和脚注 5 页；
- 数学公式 5 页；
- 表格和多栏 5 页；
- 低清、倾斜或有底纹的扫描页 5 页。

评价项分别计算字符错误、阅读顺序、标题层级、公式、表格、图注关联、漏页和幻觉；速度与显存只在质量达标后比较。默认后端优先考虑中文和复杂版面能力完整的 MinerU 本地路线；olmOCR 类 VLM可作为英文复杂页对照。最终选择以本机样本结果为准。
